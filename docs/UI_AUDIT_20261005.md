# VelocityCopy UI audit

Baseline: `3d6cfb36a3b1275e64554c536d19997733c40284`.

## Confirmed faults and resource costs

- TextScaleFactorChanged resolved/accessed window state before DispatcherQueue marshaling. All window/cache/layout access now occurs on its UI dispatcher.
- Focus restoration used the deprecated global GetFocusedElement overload; it now queries the window's XamlRoot and uses QueueItem IDs.
- RefreshQueue preconstructed up to 256 Grid/TextBlock/FontIcon trees and did so while collapsed. QueueList now stores immutable lightweight QueueItem objects, with typed x:Bind native templates and unchanged bounds/layout/styles. Collapsed refresh skips enumeration and item creation.
- A throttled progress callback still queued one full snapshot per emission while the UI was busy. The per-session mailbox stores only the newest snapshot and schedules at most one pending progress callback, rejects older sequences and verifies session identity at consumption.
- ApplySnapshot could replace paused speed/ETA with previously queued progress. Paused snapshots are rejected; inactive telemetry is now cleared consistently in both views.
- HandleDropAsync read the mutable destination/operation after awaiting StorageItems. It now captures the accepted session first and rejects a drop after retirement/cancellation/session replacement; failures cannot display an error on a replacement session.
- Repeated path tooltips allocated new boxed strings even when paths were unchanged. They now update with the path text only.

## Removed code with no runtime consumers

Removed write-only queue_refresh_deferred_, performance_window_peak_, performance_graph_clipped_ and the progress_fraction_ member whose value was only used locally. Removed the empty OnDragLeave handler/XAML registration, the unreferenced DragDrop namespace alias/operator compatibility shim and the redundant retained OptionsButton alias. Reorder still flushes one authoritative refresh through its active/force-rebuild state. Pure graph statistics/clipping helpers retain their regression coverage; graph rendering still clamps samples and advances hysteresis only on accepted samples.

Existing source contracts that required programmatic row construction or write-only caches are replaced with template/data/ownership invariants, rather than preserved with dead code.

## Microsoft documentation used

- [Keep the UI thread responsive](https://learn.microsoft.com/en-us/windows/apps/develop/performance/keep-ui-thread-responsive): dispatcher ownership, avoiding unnecessary UI work and deferring disclosed content.
- [Optimize ListView/GridView](https://learn.microsoft.com/en-us/windows/apps/develop/performance/optimize-gridview-and-listview): native virtualization, templates and recycling.
- [Data binding in depth](https://learn.microsoft.com/en-us/windows/apps/develop/data-binding/data-binding-in-depth): typed x:Bind; no reflection/bindable shim for immutable data.
- [C++/WinRT advanced concurrency](https://learn.microsoft.com/en-us/windows/apps/develop/cpp-winrt/concurrency-2): UI affinity and restored context when awaiting WinRT asynchronous operations.
- [C++/WinRT strong/weak references](https://learn.microsoft.com/en-us/windows/apps/develop/cpp-winrt/weak-references): lifetime across coroutine suspension and weak event callbacks.
- [FocusManager.GetFocusedElement](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.input.focusmanager.getfocusedelement?view=windows-app-sdk-1.8): root-specific focus ownership in multi-window WinUI.

## Verification limits

The mailbox regression exercises 10,000 updates while the consumer is blocked, latest-value delivery, stale-sequence rejection, dispatcher-discard cleanup and concurrent producer/consumer consistency. Source architecture checks cover UI-thread boundaries, templates, layout preservation, drag/drop identity and paused progress. Windows CI must link and launch the real WinUI application and run native core tests; Package must validate both installers before integration.

Compilation/launch smoke and source contracts do not prove every interactive visual route. Real-device tests remain necessary for queue keyboard/reorder/focus while copying, disclosure at 125/150/200% text/DPI, live text-size changes, cancel/session replacement during an external drop, Narrator/high contrast and ARM64 interaction. No measured RAM/throughput figure is claimed, and no public release/tag is created by this audit.
